# H1 Route Inventory — 2026-10-05

## Scope and decision

This inventory is the H1 architecture checkpoint for the controlled unified-Hono migration. It compares the frontend API calls, the production Cloudflare Worker, and the transitional Express implementation. It does **not** deploy or mutate production data. The Worker is the production authority; Express remains a rollback/local compatibility runtime until later checkpoints prove equivalence.

| Measure | Result |

| Worker routes with an exact Express declaration | 50 |
| Worker routes intentionally Worker-only or requiring Express review | 30 |

## H1 exit assessment

Every frontend endpoint pattern has a production Worker route after normalizing template parameters. The Worker and Express implementations cover the normal application route surface, but Express has maintenance-only routes that are not exposed by the Worker and must be handled explicitly in H2/H3. No route is silently treated as equivalent merely because its URL matches: authorization, Firestore effects, idempotency, and audit behavior remain checkpoint evidence below.

## H1 blockers carried forward

1. **Role/permission policy must be extracted before H2 completes.** The new staff routes accept role and permission fields; the migration must preserve the intended allowlist and add negative tests before any runtime consolidation.
2. **Financial and referral parity is not proven by route presence.** The Worker parity suite covers representative flows, but H2/H4 must compare transaction mutations, idempotency records, activity logs, domain events, and duplicate requests across both runtimes.
3. **Express maintenance routes need an explicit disposition.** Reconciliation, dashboard-summary rebuild, projection rebuild, and invalidate-all-sessions are not ordinary frontend routes but remain operational capabilities.
4. **Frontend direct Firestore reads remain outside this HTTP inventory.** They must be reviewed against Firestore rules and server-authoritative mutation boundaries during H2/H4.

## H1 exit decision

**Inventory complete for the current route surface.** No frontend API endpoint is unassigned to a production Worker route. H1 may advance to H2 only with the four blockers above recorded as acceptance criteria; no Express deletion or production cutover is authorized by this document.
