# Contributing to RQ

## Before changing code

Read `README.md` and `MAINTAINABILITY_HANDOFF.md`. Confirm the working tree is clean and start from the latest `main`.

```bash
git status --short
git pull --ff-only origin main
```

## Feature boundaries

Keep business rules in domain modules or focused server route modules. Keep `server/app.ts` focused on application assembly and shared middleware. Keep React screens focused on composition and move reusable behavior into hooks or child components.

Authentication, authorization, session lifecycle, balance operations, vehicle operations, and Firestore writes are sensitive areas. Add or update tests before changing behavior. Preserve response shapes and error codes unless the change explicitly requires a contract migration.

## Generated Vercel bundle

`api/index.js` is generated by `npm run build` but is intentionally tracked because Vercel discovers the serverless function from that path. Never hand-edit it.

After backend changes:

```bash
npm run build
git diff --stat -- api/index.js
```

Review the generated diff, scan for embedded secrets, and commit the generated bundle with the source change.

## Validation before review

```bash
npm test
npm run lint
npm run build
git diff --check
```

For deployment-related changes, also run the production smoke checks documented in `README.md`.

## Security rules

Never commit `.env` files, service-account files, private keys, tokens, or real user credentials. Do not add temporary administrative endpoints without an explicit expiry and removal plan. Do not perform destructive Firestore actions without written scope and confirmation.

## Commit guidance

Use a commit message that explains the behavior change. Keep generated artifacts in the same commit as their source change. Update `MAINTAINABILITY_HANDOFF.md` after completing a planned structural milestone, including the commit SHA and validation results.
